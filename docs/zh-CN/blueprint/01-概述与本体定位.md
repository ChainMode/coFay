# 01. 概述与本体定位

## 1.1 为什么数字社会不能只有个体化身

在 AI 代理全面进入人类社会协作网络的时代，如果所有数字实体都被设计成某个具体自然人的人格镜像，社会协作很快就会撞上一道结构性高墙：当市民向市政大厅提交许可申请、当开发者向开源基金会提交合规审计请求、或者当跨组织工作组连接一个全天候运行的医院分诊台时，调用方真正需要交互的对象并不是「张三或李四的私人化身」，而是一个**权责边界清晰、服务契约公开、即便后台值班团队轮岗也不会中断身份与公信力的公共社会角色**。

正是为了回答这一根本命题，iFay 体系从顶层确立了二元本体公式（详见 `ifay`）：

`Fay = iFay + coFay`

在这个公式中，**`Fay`** 是生态内所有数字化身的统称，严禁被单独用来特指个人化身或单指非个人实体。它由两个互补而正交的物种共同构成：

1. **`iFay`（Individual Fay，个体数字化身）**：从特定自然人——即**人类原型（Human Prime）**——复刻（Instantiate）而来，加载对齐该自然人价值观、偏好与习惯的微型 **Ego** 模型，作为人类原型在数字与物理宿主（Host，仅指终端设备或应用）上的个人延伸。
2. **`coFay`（Common Fay，公共角色化身）**：由规范化的**角色章程（`RoleCharter`）**定义、可公开寻址的功能性公共社会角色化身（规范标识符前缀为 `cofay_`，详见 `FayID`）。它不复刻任何自然人的私人性格或记忆，而是代表一个法定组织、一项治理席位或一个协作项目对外履职。

## 1.2 本体论分野：可移交的角色资产 vs. 不可解绑的人格延伸

将 `coFay` 与 `iFay` 区分开来的最底层轴线，不是底层选用了哪种大语言模型或运行在哪台服务器上，而是**「角色制度载体」与「自然人人格延伸」的伦理与产权分野**：

| 对照维度 | `iFay`（人格延伸型 Fay） | `coFay`（公共角色资产型 Fay） |
|----------|--------------------------|-------------------------------|
| **存在论本质** | 人类原型个人意志、偏好与数字能力的复刻体 | 由章程约束的制度化社会岗位、机构窗口或协作端点 |
| **与自然人的关系** | 1:1 终身归属于唯一人类原型（同一自然人可拥有多个 `iFay`），**严禁转让或买卖** | 单层归属于 `HumanID` 或 `OrganizationID`，**支持双签原子所有权过户** |
| **对外代表名义** | 代表其唯一人类原型本人行事 | 代表其**当前归属主体**（组织或个体经营者）履行公共角色职责，绝不冒充自然人 |
| **主体失能/注销处置** | 人类原型过世后转入监护人机制或受限「数字墓园」沙箱（详见 `ifay`） | 组织注销或主理人失能且未完成交接时，进入 `SUSPENDED_PENDING_SUCCESSION` 保全冻结态（详见 `FayID`） |
| **公誉链（GMChain）账户** | 绑定个体声誉；自然人遗产继承须按亲密度执行严格折损（详见 `Global-Merit-Chain`） | 绑定唯一角色 `MeritPocket`；合法双签过户时**角色延续，美誉值（MeriToken）不发生继承折损** |
| **一致性验证归口** | **iFACTS**（iFay 架构符合性测试套件） | **coFACTS**（coFay 角色章程与协议符合性测试框架） |

如果混淆这两者——例如把某个企业客服化身包装成拥有独立人格与自我意识的「数字法人」，或者反过来把某位员工个人的 `iFay` 直接当作企业官方席位对外签约——就会同时酿成双重灾难：一旦发生违约或侵权，所谓「独立数字人格」会沦为逃避法律与社会问责的黑箱；而一旦员工离职，绑在个人 `iFay` 上的机构业务关系与历史公信力又会瞬间断裂。

`coFay` 通过「制度化角色化身」消除了这一两难：席位长期存续、章程公开可验、责任穿透到人、运营灵活轮换。

## 1.3 可寻址公共角色的四大社会价值

在二元分工确立之后，`coFay` 在整个生态中承担起四项不可替代的基础设施职能：

### 第一，消除面向公众协作的寻址耦合
正如早期互联网通过域名与服务端口将「访问某项服务」与「拨通某台物理机器操作员的电话」解耦，`coFay` 让人类原型（通过受其监护的 `iFay`）与其他 `Fay` 能够直接面向职能角色寻址。需要税务政策核验时连接税务咨询 `coFay`，需要开源漏洞响应时连接项目安全席位 `coFay`——调用方验证的是该 `cofay_` 的角色章程与归属签名，无需关心后台今天由哪一个运维代理实例当值。

### 第二，杜绝「无主自治代理」问责黑洞
在 `Fay` 生态的治理铁律中，不存在游离于自然人或法定组织责任之外的「野生自治 AI」。每一个 `coFay` 从诞生起就必须锚定唯一的单层归属主体（`HumanID` 或 `OrganizationID`）；当归属主体为组织时，章程还强制要求显式登记自然人主理人（`steward_human_id`）。任何一次外部技能调用、终端控制请求或账本交互，都能沿密码学签名链无歧义地追溯至归属方与当前执勤签名者。

### 第三，沉淀跨越人员更迭的制度化公信力
公共机构、学术期刊审稿席位、开源社区维护组或商业服务窗口的社会信誉，本质上属于该公共角色长期履职的制度沉淀。通过在 **公誉链（GMChain）** 上将 `MeritPocket` 与 `cofay_` 身份一对一绑定（详见 `Global-Merit-Chain`），`coFay` 创造真实社会价值所积累的**美誉值（MeriToken，最小计量单位为 `μ` / Merit Unit）**得以持续归集于角色名下。在此必须重申：MeriToken 是衡量社会贡献与治理话语权的非货币度量凭证，不可挖矿、不可投机、不可套现，亦永不与法定货币双向兑换。

### 第四，提供与个体隐私严格隔离的公共协作平面
人类原型的个人 `iFay` 承载着大量高度敏感的生活轨迹与私人偏好，默认处于严格的隐私保护之下（详见 `FayID`）。而 `coFay` 天生面向公共或受控协作域设计：它的 `cofay_` 标识、归属组织、使命声明、允许暴露的 **技能共享协议（SSP）** 描述符以及禁止行为红线全部写入公开可验的 `RoleCharter`，让外部调用方在建立交互前即可完成零信任合规预检。

## 1.4 单仓自足与跨仓权威边界

遵循生态「单仓自足与缺席可降级」的工程纪律，`coFay` 的角色本体、无自我层架构约束、`RoleCharter` 1.0 契约、单跳管理委托约束、双签原子过户信封（`TransferEnvelope` 1.0）以及 `coFACTS` 验证准则在本仓库内完整、自足定义——即使在纯离线本地环境、不连接任何外部链节点或远端目录服务的情况下，开发者依然能够独立签发、校验并审计每一份 `RoleCharter` 与过户记录。

与此同时，本仓库严守「禁止双事实源」边界，对生态姊妹仓库已权威定义的底层机制仅作规范映射与叙述性引用：
- `hid_` / `ifay_` / `cofay_` / `org_` 标识符编码、自主主权密钥（Holder-of-Key）与组织单父层级树：详见 **FayID**；
- 人类原型、管理代理人 `iFay` 与 `coFay` 之间的委托握手链路（`Faying 1.1` Delegated Stewardship Profile）：详见 **Faying-Protocol**；
- 技能发现、JWS 描述符签名与调用鉴权：详见 **Skill-Sharing-Protocol（SSP）**；
- 宿主设备与受控资源权限边界（含 `Official_Post` 席位语义）：详见 **Control-Authority-Protocol（CAP）**；
- `MeritPocket` 链上账本绑定、非货币美誉值衰减数学与加权治理投票：详见 **Global-Merit-Chain**；
- 四层架构总纲与个体化身 `iFACTS` 规范：详见伞仓库 **ifay**。
