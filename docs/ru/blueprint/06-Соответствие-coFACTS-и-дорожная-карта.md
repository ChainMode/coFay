# 06. Фреймворк соответствия coFACTS и поэтапная дорожная карта

## 6.1 Почему `iFACTS` и `coFACTS` разделены строгой ортогональной границей

В открытой многовендорной экосистеме протоколов объективное и воспроизводимое автоматическое тестирование соответствия решает, будут ли независимые реализации надежно взаимодействовать между собой или распадутся на несовместимые декларации. Зонтичный репозиторий `ifay` определяет набор тестов **iFACTS** (*iFay Architecture Conformance Test Suite*) и уровни сертификации `iFay Ready` для индивидуальных цифровых аватаров (см. `ifay`). Зачем же экосистема поддерживает отдельный фреймворк соответствия для `coFay`, а не объединяет проверку публичных ролей внутри `iFACTS`?

Причина фундаментальна: **их базовые инварианты безопасности диаметрально противоположны**:

- В рамках `iFACTS` совместимая реализация индивидуального аватара обязана доказать корректное монтирование и согласование с персональной моделью `Ego` своего **Человека-прототипа** (`Human Prime`), выполнение эксклюзивных рукопожатий привязки 1:1 и соблюдение процедур попечительского наследования.
- В рамках `coFay` подключение любой персональной модели `Ego` представляет собой **критическое нарушение безопасности (`COFAY_EGO_FORBIDDEN`)**. Напротив, обязательные для `coFay` инварианты — сквозная привязка стюарда из числа физических лиц (`steward_human_id`), одноуровневое владение без вложенности и атомарная очистка прежних менеджеров при передаче с двойной подписью — в принципе отсутствуют у персональных аватаров `iFay`.

Поэтому экосистема применяет двусторонний пограничный перехват целевых объектов проверки:

1. **Пакет `@ifay/ifacts` проверяет исключительно реализации индивидуальных аватаров `iFay` и совместимые интеграции с хостами**, явно перехватывая целевые идентификаторы `cofay_` и перенаправляя операторов в `coFACTS` (см. `ifay`).
2. **Фреймворк `coFACTS` (*Common Fay Architecture Conformance Test Suite*) проверяет исключительно ролевые реализации `coFay`, их уставы и переходы управления**. Как только функция `runCoFactsL1Check` обнаруживает на входе идентификатор с префиксом `ifay_` или маркер типа `IFAY_MANIFEST` / `IFAY_ID`, она немедленно прекращает проверку и возвращает статус `conformance: "REJECTED_BOUNDARY"` с кодом ошибки `BOUNDARY_IFAY_USE_IFACTS`.

## 6.2 Трехуровневая прогрессивная модель соответствия в `coFACTS`

В единой методологии верификации экосистемы фреймворк `coFACTS` устанавливает три строго последовательных уровня соответствия (прежде чем претендовать на уровень L2 или L3, реализация обязана успешно пройти 100% проверок уровня L1):

| Уровень | Наименование уровня соответствия | Объект тестирования и ключевой объем проверок | Статус поставки |
| :--- | :--- | :--- | :--- |
| **L1** | **Соответствие устава и переходов состояния (`Charter & State Conformance`)** | Детерминированная автономная проверка соответствия JSON-схеме `RoleCharter` 1.0, запрета Слоя Эго, канонического перечня ролевых архетипов, одноуровневого владения и обязательной привязки стюарда — физического лица, шлюзов аутентификации абонентов для непубличных навыков SSP, целостности подписей RFC 8785 JCS + Ed25519, одношагового делегирования `iFay` без переделегирования, а также атомарной передачи владения `TransferEnvelope` 1.0 с защитой от повтора | **Поставлено в v1.0** (встроено в `@ifay/cofay`) |
| **L2** | **Межпротокольное интерфейсное соответствие (`Cross-Protocol Interface Conformance`)** | Сетевая проверка работающих конечных точек `coFay` по протоколам передачи данных: валидация подписанных JWS дескрипторов SSP по маршруту `/.well-known/skill-sharing` и взаимной аутентификации на защищенных навыках, цепочек мандатов делегированного стюардства `Faying 1.1`, блокировки выходящих за пределы `cap_bounds` команд на терминальных хостах CAP, а также раскрытия ролевой идентичности в сессиях ICP и TP | **Запланировано на Этап 2** |
| **L3** | **Эластичность и непрерывность аудита (`Elasticity & Audit Continuity`)** | Сквозные испытания отказоустойчивости и управленческие chaos-учения: проверка детерминизма поведения между параллельными безсостоянийными воркерами FayGer, неизменности локальных хеш-цепочек аудита для троек `(cofay_id, owner_id, actor_signer_id)`, автоматического перехода в защитную заморозку `SUSPENDED_PENDING_SUCCESSION` при недееспособности стюарда и непрерывной сверки атрибуции со счетом `MeritPocket` в сети **Global Merit Chain** (`GMChain`) | **Запланировано на Этап 3** |

## 6.3 Шесть автоматизированных проверок `coFACTS` L1 и формат машиночитаемого отчета

Экспортируемая из модуля `src/cofay-charter.mjs` эталонная функция без внешних зависимостей `runCoFactsL1Check(subject)` формирует детерминированные JSON-отчеты формата `report_version: "cofacts-l1-report/1.0"`:

```json
{
  "report_version": "cofacts-l1-report/1.0",
  "suite": "coFACTS",
  "level": "L1",
  "target_id": "cofay_orgservicedesk234567",
  "conformance": "PASS",
  "checks": [
    { "id": "L1-BOUNDARY-01", "name": "coFACTS vs iFACTS target boundary", "passed": true },
    { "id": "L1-NO-EGO-02", "name": "Absence of personal Ego layer attachment", "passed": true },
    { "id": "L1-TAXONOMY-03", "name": "Canonical public role archetype", "passed": true },
    { "id": "L1-OWNERSHIP-04", "name": "Single-layer ownership & natural-person steward accountability", "passed": true },
    { "id": "L1-CAPABILITIES-05", "name": "SSP caller auth gates, CAP bounds & explicit red lines", "passed": true },
    { "id": "L1-CRYPTO-06", "name": "Ed25519 JCS RoleCharter signature & actor traceability policy", "passed": true }
  ],
  "errors": []
}
```

В комплекте с эталонным раннером файл `vectors/cofay-role-charter-vectors.json` содержит **20 нормативных позитивных и негативных тестовых векторов** (`V01`–`V20`). Независимые инженерные команды, реализующие среды выполнения `coFay` или шлюзы управления на Rust, Go, Python или TypeScript, обязаны принимать все позитивные векторы и отклонять каждый негативный вектор с точным совпадением нормативного кода ошибки, прежде чем заявлять о соответствии уровню `coFACTS` L1.

## 6.4 Четырехэтапная дорожная карта развития экосистемы

Развитие `coFay` последовательно движется от криптографических уставных контрактов к живой межпротокольной совместимости и масштабному общественному управлению:

### Этап 1. Базовая нормативная спецификация и `coFACTS` L1 (выполнено, базовый релиз `2025-10-25`)
- Утверждение трехслойной онтологии публичных ролей без Слоя Эго и трех канонических ролевых архетипов релиза 1.0 (`org_service`, `functional_post` и `project_collaborator`).
- Заморозка нормативной JSON-схемы для `RoleCharter` 1.0 и конверта атомарной передачи с двойной подписью `TransferEnvelope` 1.0 (`schemas/cofay-role-charter-1.0.json` вместе с побайтово идентичной релизной триадой в каталоге `schema/2025-10-25/`).
- Поставка 20 детерминированных тестовых векторов соответствия Ed25519 + RFC 8785 JCS и эталонной библиотеки валидации и подписания `@ifay/cofay` с нулевыми внешними зависимостями.
- Выпуск полного комплекта архитектурной документации (Blueprint) и руководств быстрого старта на девяти языках.

### Этап 2. Сетевая межпротокольная интеграция конечных точек и `coFACTS` L2 (ближайшая перспектива)
- Завершение сетевых испытаний совместимости между профилем `Faying 1.1` (`coFay` Delegated Stewardship Profile), серверами навыков `SSP 1.0` и статическими индексными реестрами в среде `FayGer`.
- Выпуск автоматизированного сетевого зонда проверки `coFACTS` L2 поверх HTTP/TLS для инспекции действующих подписей `RoleCharter` и контроля обязательной аутентификации вызывающих абонентов на защищенных конечных точках SSP.

### Этап 3. Пороговое хранение ключей, мультиэкземплярная эластичность и `coFACTS` L3 (среднесрочная перспектива)
- Интеграция организационных политик пороговой мультиподписи `N-из-M` из спецификации `FayID` для коллегиального утверждения поправок к уставу советами директоров и проведения аварийных учений правопреемства в крупных общественных институтах.
- Поставка шаблонов безсостоянийных воркеров `coFay` для оркестратора контейнеров **FayGer** вместе с распределенными агрегаторами неизменяемых хеш-цепочек аудита, открывающих полную сертификацию по уровню `coFACTS` L3.

### Этап 4. Масштабная экосистема общественных сервисов на базе Global Merit Chain (`GMChain`) (долгосрочное видение)
- Запуск межотраслевого обнаружения публичных ролей в каталогах и прозрачной проверки репутационной истории счетов `MeritPocket`, позволяющих муниципальным службам, научным экспертным советам и инфраструктурным проектам открытого ПО взаимодействовать в доверенном, подотчетном и немонопольном обществе людей и агентов, опирающемся на атрибуцию немонетарного вклада **MeriToken**.
