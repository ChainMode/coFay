# Быстрый старт: концепция и интеграция coFay

Добро пожаловать в официальную документацию и эталонный инструментарий **coFay** (**Common Fay** — цифровое воплощение публичной роли). В базовой бинарной онтологии экосистемы **Fay**, выраженной формулой **`Fay = iFay + coFay`**, сущность `iFay` (**Individual Fay**) представляет собой персональный цифровой аватар, созданный на основе конкретного **Человека-прототипа** (`Human Prime`) и неразрывно согласованный с ним. В отличие от него, `coFay` — это **публично адресуемое функциональное воплощение общественной роли, определяемое и управляемое нормативным уставом `RoleCharter`**.

Независимо от того, отправляет ли Человек-прототип запрос к сервису через подконтрольный ему `iFay` или другой `Fay` вызывает совместный навык через границы организаций, вызывающей стороне не нужно искать или отслеживать конкретного оператора — физическое лицо за кулисами. Обращение к стабильной конечной точке публичной роли `cofay_<base32>` обеспечивает предсказуемое, криптографически верифицируемое и сквозным образом аудируемое взаимодействие.

## 1. Базовая ментальная модель за три минуты

Понимание `coFay` опирается на четыре структурных и этических рубежа, которые отделяют воплощение публичной роли от индивидуального аватара `iFay`:

| Измерение | `iFay` (индивидуальный цифровой аватар) | `coFay` (воплощение публичной роли) |
| :--- | :--- | :--- |
| **Онтологическая природа** | Цифровое продолжение личности, предпочтений и личной субъектности Человека-прототипа | Передаваемая публичная должность, институциональное сервисное окно или единица совместной работы |
| **Архитектурный стек** | Социальный слой + Слой взаимодействия + Когнитивный слой + **Слой Эго (`Ego Layer`)** | **Социальный слой + Слой взаимодействия + Когнитивный слой (Слой Эго строго запрещен)** |
| **Владение и передача** | Навсегда привязан к единственному Человеку-прототипу; никогда не продается, не обменивается и не передается | Одноуровневое владение со стороны `HumanID` или `OrganizationID`; поддерживает атомарную передачу с двойной подписью |
| **Проверка соответствия** | Проверяется набором тестов соответствия **iFACTS** | Проверяется исключительно фреймворком соответствия **coFACTS** |

> **Критическая проектная красная линия**: во всей экосистеме `Fay` термин **хост** (`Host`) обозначает исключительно терминальное аппаратное устройство или программное приложение, в котором размещена среда выполнения, и никогда не применяется к человеку. Юридическая и этическая ответственность за каждый `coFay` в конечном счете всегда закреплена за физическим лицом: либо напрямую за владеющим `HumanID`, либо — при владении со стороны организации — за обязательным ответственным стюардом из числа физических лиц, зарегистрированным в поле `steward_human_id`.

## 2. Предварительные требования и локальная проверка за одну минуту

Репозиторий поставляется без внешних зависимостей времени выполнения и включает нормативную JSON-схему `RoleCharter` 1.0, 20 позитивных и негативных криптографических тестовых векторов соответствия, а также инструмент проверки уровня `coFACTS` L1. При установленном **Node.js 20+** запустите полный набор проверок локально:

```bash
git clone https://github.com/ChainMode/coFay.git
cd coFay
npm test
```

При успешном выполнении автоматизированный тестовый набор последовательно проверяет семь нормативных инвариантов:

1. Побайтовое совпадение рабочей схемы `schemas/cofay-role-charter-1.0.json` и замороженного базового зеркала релиза `schema/2025-10-25/schema.json`.
2. Детерминированную сериализацию JSON по стандарту RFC 8785 JSON Canonicalization Scheme (JCS).
3. Генерацию подписей Ed25519 и защищенную от подделки верификацию для всех трех канонических архетипов публичных ролей (`org_service`, `functional_post` и `project_collaborator`).
4. Строгий запрет Слоя Эго (блокировку любого `ego_package` или подключения персональной модели личности), принудительное одноуровневое владение (блокировку вложенного владения через `ifay_` или `cofay_`) и обязательную привязку стюарда — физического лица для владельцев-организаций.
5. Ортогональное одношаговое операционное делегирование на `iFay` (разрешение выдачи и отзыва полномочий владельцем или стюардом при жестком отклонении вторичного переделегирования со стороны действующих менеджеров).
6. Атомарную передачу владения с двойной подписью (`TransferEnvelope` 1.0) с обязательной очисткой прежних менеджеров или явной повторной ратификацией, строго монотонным увеличением счетчика защиты от повтора `transfer_nonce` и непрерывной привязкой реестрового счета `MeritPocket` в сети **Global Merit Chain** (`GMChain`).
7. Формирование машиночитаемого отчета о соответствии `coFACTS` L1 наряду с детерминированным пограничным отклонением при попытке передать целевой объект `iFay` на вход `coFACTS`.

## 3. Создание и валидация первого устава `RoleCharter` 1.0

Каждый промышленный экземпляр `coFay` обязан иметь документ `RoleCharter` 1.0, подписанный по алгоритму Ed25519 его ответственным одноуровневым владельцем (или назначенным стюардом — физическим лицом, если владельцем выступает организация):

```js
import {
  signRoleCharter,
  validateRoleCharter,
  runCoFactsL1Check,
} from "@ifay/cofay";

const unsignedCharter = {
  schema_version: "1.0",
  charter_id: "chr_b4f2k7m5p3q6r4s2t4v6w3x2y4",
  charter_revision: 1,
  cofay_id: "cofay_c5g3m6n2q4r7s5t3v5w7x4y3z5",
  display_name: "Municipal Public Permit Intake Desk",
  role_archetype: "org_service",
  owner: {
    type: "organization",
    id: "org_civic-service-bureau",
  },
  steward_human_id: "hid_a3d5f7g4j2k4m6n5p2q4r6s7t2",
  managers: ["ifay_m2n4p6q7r2s4t6v5w2x4y6z2a4"],
  mission_statement:
    "Provide standardized municipal permit guidance, preliminary document verification, and application status inquiries on behalf of the Civic Service Bureau.",
  allowed_capabilities: {
    ssp_skills: [
      {
        skill_ref: "ssp://org_civic-service-bureau/permit-inquiry@1.0",
        visibility: "public",
        require_caller_auth: false,
      },
      {
        skill_ref: "ssp://org_civic-service-bureau/permit-filing@1.0",
        visibility: "restricted",
        require_caller_auth: true,
      },
    ],
    cap_bounds: {
      allowed_scopes: ["cap:document.verify", "cap:queue.dispatch"],
      max_autonomy_tier: "delegated",
      allow_irreversible_actions: false,
    },
  },
  prohibited_actions: [
    "Never impersonate any Human Prime or mount a personal Ego persona package.",
    "Never issue final administrative permit revocations without countersignature from the accountable human steward.",
  ],
  audit_policy: {
    retention_days: 365,
    log_mode: "hash_chain",
    require_actor_trace: true,
    gmc_merit_pocket_ref: "mpk_c5g3m6n2q4r7s5t3v5w7x4y3z5",
  },
  lifecycle_state: "ACTIVE",
  transfer_nonce: 0,
  issued_at: "2026-11-16T00:00:00Z",
};

const signedCharter = signRoleCharter(unsignedCharter, {
  signerId: unsignedCharter.steward_human_id,
  privateKeySeedHex:
    "0202020202020202020202020202020202020202020202020202020202020202",
});

console.log(validateRoleCharter(signedCharter)); // { valid: true, errors: [] }
console.log(runCoFactsL1Check(signedCharter).conformance); // "PASS"
```

## 4. Навигация по архитектурному проекту (Blueprint)

Изучите шесть нормативных глав архитектурного описания по порядку, чтобы детально освоить онтологическую модель, криптографические контракты управления и межпротокольную интеграцию `coFay`:

1. **[Глава 01. Обзор и онтологическое позиционирование](./blueprint/01-Обзор-и-онтология.md)** — раскрывает бинарное общественное разделение труда в формуле `Fay = iFay + coFay` и проводит онтологическую границу между передаваемыми институциональными ролевыми активами и неотчуждаемыми продолжениями личности.
2. **[Глава 02. Трехслойная архитектура и устав роли](./blueprint/02-Трехслойная-архитектура-и-устав-роли.md)** — объясняет, почему `coFay` исключает персональный Слой Эго и подчиняет Социальный слой, Слой взаимодействия и Когнитивный слой нормативному уставу `RoleCharter` 1.0.
3. **[Глава 03. Таксономия публичных ролей и сценарии применения](./blueprint/03-Таксономия-публичных-ролей-и-сценарии.md)** — описывает базовые профили полномочий и промышленные паттерны развертывания для трех канонических архетипов: `org_service`, `functional_post` и `project_collaborator`.
4. **[Глава 04. Одноуровневое владение и ответственность стюарда](./blueprint/04-Одноуровневое-владение-и-ответственность-стюарда.md)** — выстраивает сквозную цепочку полномочий, одношагового операционного делегирования и персональной подотчетности физического лица через протоколы `FayID`, `Faying 1.1`, `SSP`, `CAP` и `GMChain`.
5. **[Глава 05. Безсостоянийная среда выполнения, непрерывность репутации и передача владения с двойной подписью](./blueprint/05-Безсостоянийная-среда-непрерывность-репутации-и-передача-владения.md)** — разрешает противоречие между горизонтальным масштабированием безсостоянийных воркеров и непрерывным накоплением вклада в `MeritPocket`, а также задает спецификацию атомарной передачи владения через `TransferEnvelope` 1.0.
6. **[Глава 06. Фреймворк соответствия coFACTS и дорожная карта](./blueprint/06-Соответствие-coFACTS-и-дорожная-карта.md)** — определяет трехуровневую модель верификации `coFACTS`, ее ортогональное разграничение с `iFACTS` и четырехэтапную дорожную карту развития экосистемы.
