# 01. 概要と存在論的位置づけ

## 1.1 なぜデジタル社会は個人分身だけでは成り立たないのか

AI エージェントが人間社会の協働ネットワークへ全面的に参画する時代において、もしすべてのデジタルエンティティが「特定の自然人の人格の鏡像」として設計されていたならば、社会的コラボレーションはたちまち構造的な壁に突き当たるだろう。市民が行政窓口へ許認可申請を提出するとき、開発者がオープンソース財団へコンプライアンス監査を依頼するとき、あるいは組織横断のワーキンググループが24時間365日稼働する病院のトリアージ受付へ接続するとき、呼び出し側が真に対話したい相手は「山田さんや佐藤さん個人のプライベートな分身」ではない。求められているのは、**権限と責任の境界が明確であり、サービス契約が公開されており、バックエンドの当直チームが交代してもアイデンティティと社会的信用が途切れない公共の社会的ロール（役割）**である。

この根源的な問いに答えるため、iFay エコシステムは最上位の存在論として次の二元公式を確立している（詳細は `ifay` を参照）。

`Fay = iFay + coFay`

この公式において、**`Fay`** はエコシステム内のあらゆるデジタル分身の総称であり、個人分身のみ、あるいは非個人エンティティのみを指して単独で用いることは厳しく禁じられている。`Fay` は互いに補完し合い、かつ直交する2つの種（スピーシーズ）によって構成される。

1. **`iFay`（Individual Fay、個人デジタル分身）**：特定の自然人——すなわち**人間プライム（Human Prime）**——からインスタンス化（複製）され、その自然人の価値観・嗜好・習慣にアラインしたマイクロモデル **Ego** をロードし、デジタルおよび物理的なホスト（Host：端末デバイスまたはソフトウェアアプリケーションのみを指す）上における人間プライム個人の延長として振る舞う存在である。
2. **`coFay`（Common Fay、公共ロール分身）**：標準化された**役割憲章（`RoleCharter`）**によって定義され、公開アドレス指定が可能な機能的公共ロール分身である（正規識別子プレフィックスは `cofay_`、詳細は `FayID` を参照）。いかなる自然人の私的な性格や記憶も複製せず、法的な組織、ガバナンス上の職責ポスト、または協働プロジェクトを代表して対外的に職務を遂行する。

## 1.2 存在論的な境界：移転可能なロール資産 vs. 切り離し不可能な人格の延長

`coFay` と `iFay` を分かつ最も本質的な軸は、基盤にどの大規模言語モデルを採用しているかでも、どのサーバー上で稼働しているかでもなく、**「制度化されたロールの器」と「自然人の人格的延長」との間にある倫理および所有権の境界**にある。

| 対照軸 | `iFay`（人格延長型 Fay） | `coFay`（公共ロール資産型 Fay） |
|----------|--------------------------|-------------------------------|
| **存在論的本質** | 人間プライム個人の意思・嗜好・デジタル能力の複製体 | 役割憲章によって統制された制度的ポスト、機関窓口、または協働エンドポイント |
| **自然人との関係** | 唯一の人間プライムに 1:1 で生涯帰属（同一の自然人が複数の `iFay` を持つことは可能）。**譲渡・売買は厳禁** | `HumanID` または `OrganizationID` に単層所有され、**二重署名によるアトミックな所有権移転に対応** |
| **対外的な代表名義** | 唯一の人間プライム本人を代表して行動する | **現在の所有主体**（組織または個人事業者）を代表して公共ロールの職務を遂行し、決して自然人になりすまさない |
| **主体の能力喪失・解散時の扱い** | 人間プライムの逝去後は後見人メカニズムまたは制限付き「デジタル墓園」サンドボックスへ移行（詳細は `ifay` を参照） | 組織の解散やスチュワードの能力喪失時に引き継ぎが未完了の場合は、`SUSPENDED_PENDING_SUCCESSION` 保全凍結状態へ移行（詳細は `FayID` を参照） |
| **Global Merit Chain（GMChain / 公誉チェーン）口座** | 個人の評判に紐づく。自然人の遺産承継時には親密度に応じた厳格な減衰（ヘアカット）が適用される（詳細は `Global-Merit-Chain` を参照） | ロール固有の単一 `MeritPocket` に紐づく。適法な二重署名移転では**ロールが継続するため、MeriToken に承継減衰は発生しない** |
| **適合性検証の管轄** | **iFACTS**（iFay アーキテクチャ適合性テストスイート） | **coFACTS**（coFay 役割憲章およびプロトコル適合性テストフレームワーク） |

もしこの両者を混同すれば——たとえば企業のカスタマーサポート分身を「独立した人格と自己意識を持つデジタル法人」であるかのように装ったり、逆に従業員個人の `iFay` をそのまま企業の公式窓口として対外契約に用いたりすれば——二重の惨事を招くことになる。契約違反や権利侵害が生じた際、いわゆる「独立したデジタル人格」は法的・社会的説明責任から逃れるブラックボックスへと堕し、一方で従業員が退職した瞬間、個人の `iFay` に結びついていた機関の取引関係と蓄積された信用は一瞬にして断絶してしまう。

`coFay` は「制度化されたロール分身」という設計によってこのジレンマを解消する。ポストは長期にわたり存続し、役割憲章は公開検証可能であり、責任は自然人まで確実に貫通し、日々の運用体制は柔軟にローテーションできるのである。

## 1.3 アドレス指定可能な公共ロールがもたらす4つの社会的価値

この二元的分業が確立されたことで、`coFay` はエコシステム全体において代替不可能な4つのインフラストラクチャ機能を担う。

### 第1：公衆向け協働におけるアドレッシング結合の解消
初期のインターネットがドメイン名とサービスポートによって「あるサービスへアクセスすること」と「物理マシンの担当オペレーターに電話をかけること」を切り離したように、`coFay` は人間プライム（その監督下にある `iFay` を経由）や他の `Fay` が、職能ロールに対して直接アドレス指定することを可能にする。税務制度の確認が必要なら税務相談 `coFay` に接続し、オープンソースの脆弱性対応が必要ならプロジェクトセキュリティ窓口 `coFay` に接続すればよい。呼び出し側が検証するのは対象 `cofay_` の役割憲章と所有者署名であり、バックエンドで今日どの運用エージェントインスタンスが当直に就いているかを気にする必要はない。

### 第2：「所有者なき自律エージェント」という責任のブラックホールの根絶
`Fay` エコシステムのガバナンス鉄則において、自然人または法的組織の責任から遊離した「野生の自律 AI」は存在し得ない。すべての `coFay` は誕生した瞬間から唯一の単層所有主体（`HumanID` または `OrganizationID`）にアンカーされなければならず、所有主体が組織である場合には、役割憲章において自然人スチュワード（`steward_human_id`）を明示的に登録することが強制される。外部スキルの呼び出し、端末制御リクエスト、台帳インタラクションのいずれであっても、暗号署名チェーンを辿ることで所有主体および実行時の当直署名者を一意に特定できる。

### 第3：人員交代を超えて蓄積される制度的信用の定着
公的機関、学術誌の査読ポスト、オープンソースコミュニティのメンテナチーム、あるいは商用サービス窓口の社会的信用は、本質的にその公共ロールが長期にわたり誠実に職務を果たしてきた制度的蓄積に帰属する。**Global Merit Chain（GMChain / 公誉チェーン）** 上で `MeritPocket` と `cofay_` アイデンティティを 1:1 で紐づけることにより（詳細は `Global-Merit-Chain` を参照）、`coFay` が真の社会的価値を創出して得た**MeriToken（最小計量単位は `μ` / Merit Unit）**は継続的にそのロールの名義へと集約される。ここで改めて強調しておくと、MeriToken は社会的貢献度とガバナンス発言権を測る非貨幣的な計量証憑であり、マイニング不可・投機不可・換金不可であって、法定通貨との双方向交換も決して行われない（never exchanged with fiat currency）。

### 第4：個人のプライバシーから厳格に隔離された公共協働プレーンの提供
人間プライムの個人 `iFay` は、極めて機微な生活履歴や私的嗜好を保持しているため、デフォルトで厳重なプライバシー保護下に置かれる（詳細は `FayID` を参照）。これに対し、`coFay` は最初から公共領域または管理された協働ドメイン向けに設計されている。その `cofay_` 識別子、所有組織、ミッション声明、公開が許可された **Skill-Sharing-Protocol（SSP、スキル共有プロトコル）** ディスクリプタ、および禁止事項のレッドラインはすべて公開検証可能な `RoleCharter` に記述されるため、外部の呼び出し側は対話を開始する前にゼロトラストでの事前コンプライアンス検証を完了できる。

## 1.4 単一リポジトリ自己完結性とリポジトリ間の権威境界

エコシステムのエンジニアリング規律である「単一リポジトリ自己完結性と不在時のグレースフルデグラデーション（縮退運転可能性）」に従い、`coFay` のロール存在論、自己層排除アーキテクチャ制約、`RoleCharter` 1.0 契約、1ホップ管理委任制約、二重署名アトミック移転エンベロープ（`TransferEnvelope` 1.0）、および `coFACTS` 検証基準はすべて本リポジトリ内で完全に自己完結する形で定義されている。外部のチェーンノードやリモートディレクトリサービスに一切接続しない完全オフラインのローカル環境であっても、開発者は単独で各 `RoleCharter` や所有権移転レコードを発行・検証・監査することができる。

同時に、本リポジトリは「二重の信頼源（Dual Source of Truth）の禁止」という境界を厳守しており、姉妹リポジトリですでに権威ある定義がなされている基盤メカニズムについては、正規マッピングと参照のみを行う。

- `hid_` / `ifay_` / `cofay_` / `org_` 識別子エンコーディング、自己主権型鍵保持（Holder-of-Key）、および組織の単一親階層ツリー：**FayID** を参照。
- 人間プライム、管理エージェント `iFay`、および `coFay` 間の委任ハンドシェイクチェーン（`Faying 1.1` Delegated Stewardship Profile）：**Faying-Protocol** を参照。
- スキル発見、JWS ディスクリプタ署名、および呼び出し認証：**Skill-Sharing-Protocol（SSP）** を参照。
- ホストデバイスおよび制御対象リソースの権限境界（`Official_Post` ポストセマンティクスを含む）：**Control-Authority-Protocol（CAP）** を参照。
- `MeritPocket` オンチェーン台帳バインディング、非貨幣的 MeriToken の時間減衰数理、および重み付きガバナンス投票：**Global-Merit-Chain** を参照。
- 四層アーキテクチャ総論および個人分身向け `iFACTS` 仕様：アンブレラリポジトリ **ifay** を参照。
