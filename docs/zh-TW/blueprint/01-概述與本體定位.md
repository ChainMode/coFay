# 01. 概述與本體定位

## 1.1 為什麼數位社會不能只有個體化身

在 AI 代理全面進入人類社會協作網路的時代，如果所有數位實體都被設計成某位特定自然人的人格鏡像，社會協作很快就會撞上一道結構性高牆：當市民向市政服務中心遞交許可申請、當開發者向開源基金會提出合規稽核請求，或是當跨組織工作小組連線至全天候運作的醫院檢傷分診台時，呼叫端真正需要互動的對象並不是「某甲或某乙的私人化身」，而是一個**權責邊界清晰、服務契約公開、即便後台值班團隊輪調也不會中斷身分與公信力的公共社會角色**。

正是為了回應這項根本命題，iFay 體系從頂層確立了二元本體公式（詳見 `ifay`）：

`Fay = iFay + coFay`

在這個公式中，**`Fay`** 是生態內所有數位化身的統稱，嚴禁單獨用來特指個人化身或單指非個人實體。它由兩個互補且正交的物種共同構成：

1. **`iFay`（Individual Fay，個體數位化身）**：從特定自然人（即**人類原型，Human Prime**）復刻（Instantiate）而來，載入對齊該自然人價值觀、偏好與生活習慣的微型 **Ego** 模型，作為人類原型在數位與實體宿主（Host，僅指終端裝置或應用軟體）上的個人延伸。
2. **`coFay`（Common Fay，公共角色化身）**：由規範化的**角色章程（`RoleCharter`）**定義、可公開尋址的功能性公共社會角色化身（規範識別碼前綴為 `cofay_`，詳見 `FayID`）。它不復刻任何自然人的私人性格或記憶，而是代表一個法定組織、一項治理席位或一個協作專案對外履職。

## 1.2 本體論分野：可移交的角色資產 vs. 不可解綁的人格延伸

將 `coFay` 與 `iFay` 區分開來的最底層軸線，並非底層選用了哪種大型語言模型或執行在哪一台伺服器上，而是**「角色制度載體」與「自然人人格延伸」在倫理與產權上的根本分野**：

| 對照維度 | `iFay`（人格延伸型 Fay） | `coFay`（公共角色資產型 Fay） |
|----------|--------------------------|-------------------------------|
| **存在論本質** | 人類原型個人意志、偏好與數位能力的復刻體 | 由章程約束的制度化社會職務、機構窗口或協作端點 |
| **與自然人的關係** | 1:1 終身歸屬於唯一人類原型（同一自然人可擁有多個 `iFay`），**嚴禁轉讓或買賣** | 單層歸屬於 `HumanID` 或 `OrganizationID`，**支援雙簽原子所有權過戶** |
| **對外代表名義** | 代表其唯一人類原型本人行事 | 代表其**當前歸屬主體**（組織或獨立執業者）履行公共角色職責，絕不冒充自然人 |
| **主體失能/註銷處置** | 人類原型過世後轉入監護人機制或受限「數位墓園」沙箱（詳見 `ifay`） | 組織註銷或主理人失能且未完成交接時，進入 `SUSPENDED_PENDING_SUCCESSION` 保全凍結態（詳見 `FayID`） |
| **公譽鏈（GMChain）帳戶** | 綁定個體聲譽；自然人遺產繼承須依社會親密度執行嚴格折損（詳見 `Global-Merit-Chain`） | 綁定唯一角色 `MeritPocket`；合法雙簽過戶時**角色延續，美譽值（MeriToken）不發生繼承折損** |
| **一致性驗證歸口** | **iFACTS**（iFay 架構符合性測試套件） | **coFACTS**（coFay 角色章程與協定符合性測試框架） |

如果混淆這兩者，例如把某個企業客服化身包裝成擁有獨立人格與自我意識的「數位法人」，或者反過來把某位員工個人的 `iFay` 直接當作企業官方席位對外簽約，就會同時釀成雙重災難：一旦發生違約或侵權，所謂「獨立數位人格」會淪為逃避法律與社會問責的黑箱；而一旦員工離職，綁定在個人 `iFay` 上的機構業務關係與歷史公信力又會瞬間斷裂。

`coFay` 透過「制度化角色化身」消除了這項兩難：席位長期存續、章程公開可驗、責任穿透到人、維運彈性輪調。

## 1.3 可尋址公共角色的四大社會價值

在二元分工確立之後，`coFay` 在整個生態中承擔起四項不可替代的基礎設施職能：

### 第一，消除面向公眾協作的尋址耦合
正如早期網際網路透過網域名稱與服務連接埠，將「存取某項服務」與「撥通某台實體機器作業員的電話」解耦，`coFay` 讓人類原型（透過受其監護的 `iFay`）與其他 `Fay` 能夠直接面向職能角色尋址。需要稅務法規核驗時連線至稅務諮詢 `coFay`，需要開源漏洞通報應變時連線至專案資安席位 `coFay`；呼叫端驗證的是該 `cofay_` 的角色章程與歸屬簽章，無需關心後台今天是由哪一個維運代理執行個體當值。

### 第二，杜絕「無主自治代理」問責黑洞
在 `Fay` 生態的治理鐵律中，不存在游離於自然人或法定組織責任之外的「野生自治 AI」。每一個 `coFay` 從誕生起就必須錨定唯一的單層歸屬主體（`HumanID` 或 `OrganizationID`）；當歸屬主體為組織時，章程更強制要求明確登記自然人主理人（`steward_human_id`）。任何一次外部技能呼叫、終端宿主控制請求或帳本互動，都能沿著密碼學簽章鏈毫無歧義地追溯至歸屬方與當前執勤簽章者。

### 第三，沉澱跨越人員更迭的制度化公信力
公共機構、學術期刊審稿席位、開源社群維護團隊或商業服務窗口的社會信譽，本質上屬於該公共角色長期履職的制度沉澱。透過在 **公譽鏈（GMChain）** 上將 `MeritPocket` 與 `cofay_` 身分一對一綁定（詳見 `Global-Merit-Chain`），`coFay` 創造真實社會價值所累積的**美譽值（MeriToken，最小計量單位為 `μ` / Merit Unit）**得以持續歸集於角色名下。在此必須重申：MeriToken 是衡量社會貢獻與治理話語權的非貨幣度量憑證，不可挖礦、不可投機、不可套現，亦永不與法定貨幣雙向兌換。

### 第四，提供與個體隱私嚴格隔離的公共協作平面
人類原型的個人 `iFay` 承載了大量高度敏感的生活軌跡與私人偏好，預設處於嚴格的隱私保護之下（詳見 `FayID`）。而 `coFay` 天生針對公共或受控協作域設計：它的 `cofay_` 識別碼、歸屬組織、使命聲明、允許公開的 **技能共享協定（SSP）** 描述符，以及禁止行為紅線全部寫入公開可驗的 `RoleCharter`，讓外部呼叫端在建立互動前即可完成零信任合規預檢。

## 1.4 單一儲存庫自足與跨儲存庫權威邊界

遵循生態「單一儲存庫自足與缺席可降級」的工程紀律，`coFay` 的角色本體、無自我層架構約束、`RoleCharter` 1.0 契約、單跳管理委託約束、雙簽原子過戶信封（`TransferEnvelope` 1.0）以及 `coFACTS` 驗證準則皆在本儲存庫內完整且自足地定義。即使在純離線的本機環境、不連線任何外部鏈節點或遠端目錄服務的情況下，開發者依然能夠獨立簽發、檢核並稽核每一份 `RoleCharter` 與過戶紀錄。

與此同時，本儲存庫嚴守「禁止雙重事實來源（Single Source of Truth）」邊界，對生態姊妹儲存庫已權威定義的底層機制僅作規範映射與敘述性引用：
- `hid_` / `ifay_` / `cofay_` / `org_` 識別碼編碼、自主主權金鑰（Holder-of-Key）與組織單親階層樹：詳見 **FayID**；
- 人類原型、管理代理人 `iFay` 與 `coFay` 之間的委託握手鏈路（`Faying 1.1` Delegated Stewardship Profile）：詳見 **Faying-Protocol**；
- 技能探索、JWS 描述符簽章與呼叫端權限驗證：詳見 **Skill-Sharing-Protocol（SSP）**；
- 宿主裝置與受控資源權限邊界（含 `Official_Post` 席位語意）：詳見 **Control-Authority-Protocol（CAP）**；
- `MeritPocket` 鏈上帳本綁定、非貨幣美譽值衰減數學模型與加權治理投票：詳見 **Global-Merit-Chain**；
- 四層架構總綱與個體化身 `iFACTS` 規範：詳見傘型儲存庫 **ifay**。
